Name, slot, value

        

          A variable is a name attached to a
          value sitting in a memory slot. Creating the binding
          does not duplicate everything—only the name points at the value.
          Assigning a primitive (number, string, boolean) usually copies the
          value; assigning an object shares that same object until you rebind
          the name.
        


        
Where the name lives

        

          The diagram’s left column is not “just a label in the textbook.” The
          runtime really stores that binding in a small slot—often inside the
          current function’s
          call-stack frame
          (think: a sticky note on your desk that says “items → that box”). The
          right column is the value—for objects and arrays, usually a
          separate block on the heap (a warehouse of boxes the
          program reserved). The arrow is the connection: desk note → warehouse
          box. Rebind rewrites the note; mutate opens the same box and changes

          Rebind (x = 7) updates
          x’s name slot to a new value or pointer. The old data
          sticks around only if something else still points at it; otherwise it
          can be collected (see
          garbage collection). The faded unbound cell in the lab is a teaching prop—in a
          real runtime that memory is not left sacred forever; once unreachable,
          the GC (or free) can reuse it.
