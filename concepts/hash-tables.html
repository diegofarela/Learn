Hash tables

Data structures key → bucket · chaining · avg O(1) load 0.38 · n 3

A hash table maps keys to values by computing an index into an array of buckets. Hash the key, land in a slot, store or find the pair there. When two keys land in the same bucket, this demo uses separate chaining—a short linked list hanging off that index.

Hash function

        

          The hash function turns a key into an integer index.
          A good one spreads keys evenly across buckets. This demo uses a toy
          sum of character codes modulo bucket count—enough to see the idea,
          not crypto-strong. Real tables use stronger mixers, but the contract
          is the same: index = hash(key) % N.
        


        
Buckets

        

          The underlying store is an
          array
          of length N. Each slot is a bucket. Empty
          buckets hold nothing; occupied ones hold one or more entries. You never
          scan the whole array for a key—you jump straight to the hashed index.
        


        
Collisions

        

          Different keys can hash to the same index. That is a
          collision. With separate chaining, the
          bucket becomes a
          linked list
          (or similar chain) of key–value pairs. Lookup walks that short chain
          until it finds a matching key—or runs out.
        


        
Load factor

        

          Load factor α = n / N (entries divided by buckets).
          As α grows, chains get longer and average cost creeps up. Tables
          often resize (rehash into a larger array) when α crosses a
          threshold so operations stay near constant time.
