Heaps

Data structures min-heap · sift-up / sift-down · complete binary tree size 5

A binary heap is a complete binary tree stored in an array, with a priority rule at every node—not the heap memory region. This demo is a min-heap: the smallest key sits at the root, and each parent is ≤ its children. Priority queues are often implemented as heaps — see priority queues.

When this is useful

  • A hospital triage or support-ticket board that always pops the highest priority.
  • A game AI or maps app running Dijkstra/A* for “next closest” exploration.
  • A live leaderboard feed where you only need the current top score, not full sort every frame.

Tree shape, array guts

        

          A heap is always a
          complete
          binary tree: levels fill
          left to right. That shape maps cleanly onto an array: for index
          i, parent is ⌊(i−1)/2⌋, children are 2i+1 and
          2i+2. No pointers required—the demo shows both views of the
          same structure.

Heap vs BST

        

          A
          binary search tree
          orders every left/right path for search. A heap only cares about
          parent–child priority and completeness—siblings can be in any order.
          That makes heaps excellent for “next most important item,” not for
          arbitrary key lookup.
        


        
Priority queues

        

          A priority queue is the ADT (“always serve the highest-priority item”).
          A binary heap is the classic implementation. Try the
          priority queues
          lab for the ADT view; this heap page is the concrete structure behind
