Object-oriented programming

Programming models classes · objects · inheritance objects 0

Object-oriented programming (OOP) models software as interacting objects: each bundles data (fields) with behavior (methods). A class is the blueprint; instances are live objects. Contrast with functional programming, which emphasizes composing pure functions over mutable objects. Named structures like Strategy and Observer live in design patterns.

Encapsulation

        

          Fields stay behind the object’s interface. Callers use methods instead of
          poking at raw state—so you can change internals without breaking clients.
        


        
Inheritance

        

          A subclass reuses and extends a superclass. Dog inherits
          name and speak() from Animal, then
          adds breed. The tree above shows that “is-a” link.
        


        
Polymorphism

        

          The same message—speak()—can mean different things depending
          on the runtime type. A Dog may bark while another
          Animal subclass meows, yet callers treat them uniformly.
