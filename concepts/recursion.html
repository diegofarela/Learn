Recursion

Algorithms base case · recursive case · self-call depth 0

Recursion solves a problem by calling the same function on a smaller piece—until a base case answers directly. Each pending call sits on the call stack (the same stack ADT idea: last frame in, first out).

Base case

        

          The base case is the smallest input you can answer
          without calling yourself again. For factorial, fact(0)
          (or fact(1)) returns 1. Without it, recursion
          never stops—and the
          call stack
          grows until it overflows.
        


        
Recursive case

        

          The recursive case reduces the problem:
          fact(n) = n * fact(n - 1). Each call must move toward the
          base case. If it doesn’t, you get infinite recursion in theory—and a
          crash in practice.
        


        
Connection to the call stack

        

          Every recursive call pushes a frame; every return
          pops one. That’s why deep recursion needs stack space, and why
          the
          stack
          ADT and the
          call stack
          are the same mental model.
        


        
When to prefer iteration

        

          If a problem is a straight loop (countdown, summing an array), a
          for/while is usually clearer and cheaper—no
          frame-per-step overhead. Prefer recursion when the problem is naturally
          tree-shaped (parse trees, divide-and-conquer, DFS) and the depth stays
          reasonable—or when the language optimizes tail calls.
