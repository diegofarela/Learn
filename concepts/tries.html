Tries

Data structures prefix tree · char edges · autocomplete words 4 · nodes 0

A trie (prefix tree) stores strings character by character. Shared prefixes share a path from the root—so cat and car diverge only at the last letter. That makes prefix search and autocomplete natural: walk the prefix, then collect everything below.

When this is useful

  • Reach for this when the query is a prefix—autocomplete, spell-check dictionaries, IP/routing prefixes, shared namespaces.
  • Needed when many strings share beginnings and you want to share that storage and search path instead of hashing each whole key.
  • Prefer a hash table for exact whole-key lookup with no prefix work.

Shared prefixes

        

          Unlike a
          BST
          (which stores whole keys in nodes), a trie node’s
          position is the key so far. Edges are labeled by characters.
          An end-of-word flag marks complete strings so
          do can exist alongside dog.

          Here m is the length of the string—not the number of words
          stored. That independence from dictionary size is why tries shine for
          dictionaries and autocomplete.
