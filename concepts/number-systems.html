Foundations base-10 · base-2 · base-16 · two's complement n = 42

The same quantity can be written in many bases. Decimal is familiar; computers store binary bits; hex packs four bits per digit. Edit any field below—the others update live. Toggle two's complement to see how an 8-bit machine encodes negatives.

When this is useful

  • Reach for this when reading addresses, colors, opcodes, or dumps written in hex—and when converting them without mistakes.
  • Needed to prevent signed/unsigned and overflow bugs: two’s complement is how machines store negatives in fixed-width ints.
  • Use it whenever bit width matters (8/16/32/64-bit) and “the same bits” mean different values depending on interpretation.

Bases share place values

        

          In base b, digit positions are powers of b. Binary
          uses powers of two; hex uses powers of sixteen. That is why
          0x2A and 00101010 name the same byte—see
          Binary & bits
          to flip those bits by hand.
        


        
Two's complement

        

          Unsigned bytes run 0…255. Signed 8-bit two's complement runs
          −128…127: negate by flipping every bit and adding one. So
          −1 is all ones (0xFF). Masks and shifts that
          build on this live in
          bit manipulation.
