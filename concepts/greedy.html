Greedy

Algorithms local best · commit · no undo coins 0

A greedy algorithm builds a solution by always taking the locally best option and never revisiting that choice. For US coin change, that means “largest denomination that still fits.” On canonical currencies this is optimal; on some coin systems it fails—and dynamic programming is the safe fallback.

The greedy choice

        

          At every step the algorithm asks only: which legal option looks best
          right now? For change-making that is the largest coin ≤ remaining
          amount. For activity selection it is “finish earliest.” There is no
          search tree and no memo table—just commit and shrink the leftover
          problem.

When greedy fails

        

          US coins are a canonical system: greedy always uses the fewest
          coins. Try denominations {1, 3, 4} to make 6: greedy takes 4 + 1 + 1
          (three coins), but 3 + 3 is better. That is where
          DP
          (or exhaustive search) earns its keep—optimal substructure without the
          “local best is global best” guarantee.
