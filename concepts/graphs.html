Graphs

Data structures vertices + edges · directed or undirected · adjacency edges 6

A graph is a set of vertices (nodes) plus edges that connect them. Unlike a binary tree, there is no single root rule: edges can form cycles, forks, and arbitrary networks. Traversals like BFS and DFS walk those connections layer by layer or deep-first.

When this is useful

  • Reach for this when relationships are the data—social links, dependencies, roads, call graphs, recommendation edges.
  • Needed whenever connectivity, paths, or cycles matter more than a single parent hierarchy (trees are a special case).
  • Pair with BFS / DFS (and later shortest paths / MSTs) once the model is a graph.

Adjacency list vs matrix

        

          An adjacency list stores, for each vertex, the
          neighbors it touches—space about
          O(V + E), great for sparse graphs. An
          adjacency matrix is a V×V grid of 0/1 (or weights)—
          O(V²)
          space, O(1) edge checks. The demo’s side panel mirrors a list; the
          highlighted edges are what a matrix row would mark as 1.
        


        
Directed vs undirected

        

          Undirected edges are mutual: A–B means both directions. Directed
          edges (arcs) are one-way: A→B does not imply B→A. Toggle the mode to
          see arrowheads and how the neighbor list changes for the same
          underlying pairs.
