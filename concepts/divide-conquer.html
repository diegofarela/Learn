Divide & conquer

Algorithms split · solve · merge · D&C phase ready

Divide and conquer solves a problem by splitting it into smaller pieces of the same shape, solving those (often with recursion), then combining the answers. Classic sorting algorithms like merge sort follow this pattern—and the cost is usually analyzed with Big-O recurrences such as T(n) = 2T(n/2) + O(n).

Three moves

        

          Divide cuts the input (here, an array) into halves.
          Conquer sorts each half—recursively, until a single
          element is trivially sorted. Combine merges two
          sorted runs into one sorted list. That merge is the linear work that
          turns two answers into one.
        


        
Why it helps

        

          Splitting balances the work: each level of the tree does about
          O(n) merge work, and there are
          O(log n) levels—so merge sort is
          O(n log n). See
          Big-O
          for how that growth compares to nested loops.
