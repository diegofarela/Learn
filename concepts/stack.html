Stack

Data structures LIFO · push / pop / peek · O(1) size 3

A stack ADT is a collection you only touch at the top. Push adds, pop removes, peek looks without removing. Last in is first out—like a pile of plates, or the call stack your program uses for nested function calls (same LIFO idea, different job).

When this is useful

  • Powering Undo in a notes or drawing app (last action first).
  • Parsing nested UI routes, JSON, or matched brackets in a code editor.
  • Modeling the call stack when debugging “which screen opened which modal.”

For mastery

          
    
            
  • 
              Invariant
              Only the top is accessible: push/pop/peek hit one end.
              LIFO — the last pushed item is the next popped.
            
    • 
            
  • 
              When / when not
              Use for undo, matching delimiters, DFS frames, and the
              call stack.
              Not when oldest-first fairness is the goal — use a
              queue.
            
    • 
            
  • 
              Common failure
              Pop/peek on empty; treating middle elements as addressable;
              confusing LIFO with FIFO.
            
    • 
            
  • 
              Proof shape
              After any legal push/pop sequence, the remaining items are a
              prefix of the push history (stack discipline).
            
    • 
            
  • 
              Assumes
              A single logical top; no random access into the body of the stack.
