Dynamic programming

Algorithms overlap · memo · table fill calls 0

Dynamic programming (DP) tackles problems with overlapping subproblems: the same smaller question shows up again and again. Instead of recomputing (as naive recursion does), you store each answer in a table— memoization or bottom-up fill—so total work drops from exponential to roughly linear in the table size.

Overlapping subproblems

        

          In naive fib(n), fib(3) is computed many
          times from different parents. The call tree fans out exponentially.
          That explosion is the clue that DP can help: the same answers are
          needed repeatedly.
        


        
Memoization / table

        

          Store fib(i) once. Top-down memoization caches recursive
          results; bottom-up fills dp[0…n] in order. Either way
          each index is solved once—about O(n) time and space for
          Fibonacci.
