HTTP

Networks request · response · status step 0/5

HTTP is how browsers and APIs talk: a client sends a request (method + path + headers), a server answers with a status and a body. Step through an exchange below. Names resolve via DNS; bytes usually ride TCP through sockets on the application layer. Resource-oriented APIs often follow REST (an API style that uses HTTP—not a synonym for HTTP itself). Encrypt the wire with TLS / HTTPS.

When this is useful

  • Every web/mobile API call, browser navigation, and webhook delivery.
  • Designing REST resources, status codes, and caching headers for a SaaS.
  • Debugging CORS, redirects, and content-type issues in DevTools.
