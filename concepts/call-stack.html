Call stack

Algorithms frames · return address · locals · LIFO frames 0

The call stack is how the runtime tracks nested function calls. Each call pushes a frame; each return pops one—the same LIFO idea as the stack ADT you implement yourself. It’s also what grows under recursion.

Frames

        

          A stack frame (activation record) is one invocation’s
          bookkeeping: who called you, your locals, and where to resume. The top
          frame is the function running right now; frames below are callers
          waiting to continue.
        


        
Return addresses

        

          When main calls a, the machine saves the
          return address—the next instruction in
          main after the call. When a finishes, that
          address is popped and control jumps back. Nested calls stack return
          addresses the same way plates stack.
        


        
Locals

        

          Each frame owns its own locals. a’s x is not
          b’s y. That isolation is why
          recursion
          works: every fact(n) keeps a separate n.
        


        
Overflow intuition

        

          The call stack has finite space. Too many nested calls (often runaway
          recursion without a base case) exhaust it—a
          stack overflow. Prefer iteration for deep linear
          work, or raise limits carefully when the tree is legitimately deep.
        


        

          Contrast the runtime call stack with the

          recursion
          uses both ideas at once.
