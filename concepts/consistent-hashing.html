Consistent hashing

Distributed ring · shards · minimal remap nodes 3

Consistent hashing places nodes and keys on a ring so adding or removing a node only remaps a small fraction of keys—unlike hash(key) % N. It builds on hash tables / hashing and shows up in caches and sharded stores.

When this is useful

  • Sharding a cache or KV store across nodes so adding a server remaps little data.
  • CDN and load-balancer ring designs for sticky-ish distribution.
  • Partitioning chat rooms or IoT devices across a growing cluster.
