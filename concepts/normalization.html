Normalization

Databases 1NF → 2NF → 3NF form raw

Normalization reshapes tables to reduce redundancy and update anomalies—atomic columns (1NF), full dependence on the key (2NF), no transitive deps (3NF). Here it means schema design, not Unicode text encoding / normalization. Related: relational model and SQL.

When this is useful

  • Stop storing the same address five times across user tables in a CRM.
  • Schema design so updating a product name doesn’t require rewriting every order.
  • Knowing when to denormalize on purpose for a read-heavy feed.
