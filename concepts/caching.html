Caching

Systems hit / miss · LRU · locality hits 0 · misses 0

A cache is a small, fast store in front of a larger, slower one (here: RAM). Look in the cache first—a hit is cheap; a miss fetches from RAM and usually installs a copy. When the cache is full, LRU drops the least recently used line. Related: virtual memory (pages as another layer) and memory & pointers.

When this is useful

  • CDN edge caches for images, Redis for session data, browser HTTP cache.
  • Speeding a product page that hits the DB on every refresh.
  • Invalidation design when an admin edits a price that must show immediately.

Hit vs miss

        

          On each request, check tags in the cache. Matching tag →
          hit (serve from cache, update LRU order). No match →
          miss: read from RAM, place a copy in the cache, and if
          every line is busy, evict one first.
        


        
LRU eviction

        

          Least recently used assumes temporal locality: what you
          touched lately you’ll touch again. The demo keeps lines in recency
          order; a miss with a full cache drops the coldest line.
